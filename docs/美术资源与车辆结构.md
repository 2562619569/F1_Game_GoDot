# 美术资源与车辆结构规范

车壳模型与轮件（轮毂/轮胎/刹车盘）分离管理。轮件资产以**枢纽（pivot）为原点**建模并只存模型；车壳资产定义**前轴/后轴位置 + 车体最宽处半宽**。运行时（及编辑器预览）先以**轮毂定轮位**：轮毂外盘面齐车身边线（轮位 x = ±(body_width − hub.outer)），再把轮胎套上（胎中线对齐轮毂桶身几何中线 hub.mid_x）；滚动/转向围绕轮心旋转。

## 一、目录结构

```
F1/art/                      # 美术资源根（整目录 gitignore，不入库）
├── cars/
│   └── <car_id>/            # 车壳资产，目录名 = Car-car 配表 id（如 601/602/603）
│       ├── body.glb         # 车壳模型
│       └── body.json        # 元数据：前/后轴 yz + 车体半宽等（编辑器读写）
├── wheels/
│   └── <model>/             # 轮毂资产，如 sport_v1（Cosmetic 外观件表 wheel 类别）
│       ├── hub.glb          # 轮毂模型（纯外观，无物理量）
│       └── hub.json         # 元数据：center 等
├── tires/
│   └── <model>/             # 轮胎资产，如 stock_v1（原厂默认胎，非改件）
│       ├── tire.glb         # 轮胎模型
│       └── tire.json        # 元数据：center + radius/width 物理量
└── brakes/
    └── <model>/             # 刹车盘资产（含卡钳），前/后轴各一款
        ├── disc.glb         # 刹车盘模型
        └── disc.json        # 元数据：center
```

- `<car_id>` 取配表 `Car-car` 表的 `id`（数字字符串，如 `601`），同时是目录名与 JSON 里的 `id`；配表加车后 `tools/art_editor/server.py` 的 `/api/cars` 自动列入编辑器清单。
- 轮毂 `<model>` 取 `Cosmetic-cosmetic` 外观件表 wheel 类别的 `model` 列；轮胎 `<model>` 取 `Part-part` 改件表 tires 类别的 `model` 列（另有原厂胎 `stock_v1` 不属于任何改件）；刹车盘暂无配表项，默认 `front_v1`/`rear_v1`。均用小写字母、数字、下划线，同时是目录名与 JSON 里的 `id`。**各车默认轮毂**由 `Car-car` 表的 `wheel` 列指定（玩家未选外观件 / AI 装配时生效），空值回退 `CarMeshBuilder.DEFAULT_HUB`。
- 模型统一 GLB（glTF 2.0 二进制），单位米。
- `tools/art_editor/index.html` 是元数据编辑器（代码入库，双击即用）。
- 组合零件包可用 `tools/art_editor/split_parts_glb.py` 拆分为单项资产并自动落位（按枢纽重锚 + 实测胎 radius/width）。

## 二、元数据 Schema

### hub.json（轮毂）/ tire.json（轮胎）/ disc.json（刹车盘）

```json
{
  "version": 1,
  "id": "sport_v1",
  "name": "Sport Wheels V1",
  "model": "hub.glb",
  "center": [0.0, 0.0, 0.0],
  "outer": 0.0919,
  "mid_x": -0.041,
  "radius": 0.2524,
  "width": 0.2657
}
```

| 字段 | 说明 |
| --- | --- |
| `center` | 枢纽点（模型局部空间）。轮毂/刹车盘 = 安装位（两者用同一安装坐标即得正确相对位置）；轮胎 = 轮心（轮宽中面与轮轴交点）。运行时该点对齐车壳轮位，旋转围绕它进行；资产按枢纽为原点建模时恒为 `[0,0,0]` |
| `outer` | 轮毂必填。原点到**外盘面**的 x 距离（+X 为外侧，实测值由拆分脚本写出）。轮位以它定义：x = ±(body_width − outer)，外盘面齐车身边线。轮毂盘面深浅不一（不同款 0.07~0.13），不能用 width/2 近似，否则盘面埋进胎内呈内凹 |
| `mid_x` | 轮毂必填。原点到**桶身几何中线**的 x 偏移（实测值）。套胎基准：轮胎中线对齐该线（左右轮位随朝向翻转自动镜像），保证胎对称包裹轮毂 |
| `radius` | 轮胎必填。轮胎外半径（米，轮轴平面最大半径），运行时同步给物理轮 `tire_radius`（决定悬挂射线长度与驱动力臂） |
| `width` | 轮胎必填。胎宽（米）；无轮毂资产或缺 `outer` 元数据时轮位退回胎侧齐边 x = ±(body_width − width/2) |

### body.json（车壳）

```json
{
  "version": 2,
  "id": "601",
  "name": "Brute Power",
  "model": "body.glb",
  "body_width": 0.92,
  "front_axle": { "y": 0.35, "z": -1.25 },
  "rear_axle":  { "y": 0.35, "z": 1.25 },
  "materials": {
    "headlight": "headlight",
    "brake_light": "brake_light",
    "body": "hull"
  },
  "material_presets": {
    "paint": { "material": "hull", "params": { "color": "#c23a2f", "flake_amount": 0.5, "clearcoat": 1.0 } },
    "headlight_lens": null,
    "glass": { "material": "glass", "params": { "color": "#05060a", "alpha": 1.0 } }
  },
  "anchors": {
    "spoiler": { "position": [0.0, 0.0, 0.0] }
  }
}
```

| 字段 | 说明 |
| --- | --- |
| `body_width` | 车体最宽处**半宽**（米，中线到最宽边缘的 x 距离）。四轮位横向 x 由此推导 |
| `front_axle` / `rear_axle` | 前/后轴位置 `{y, z}`（x 恒 0）。`z` 为轴距方向位置（车头 −Z），`y` 为**静止时轮心在车身局部空间的高度**（「标定即静态位」：`vehicle.gd` initialize() 会把物理挂点上抬静态下垂量 `行程×(1−静载比)`，静止轮心恰落回标定值，标多少游戏里就是多少） |
| `materials` | 可选。语义材质槽位 → GLB 内材质名（null/缺省 = 未标记）。`brake_light` 已消费：刹车时该材质点亮红色自发光（详见第六节）；`headlight` / `body` 预留给后续车灯/车漆逻辑 |
| `material_presets` | 可选。预设材质球（引擎效果）→ `{material, params}`（null = 未绑定）。三槽位：`paint` 车漆 / `headlight_lens` 大灯透明罩 / `glass` 车玻璃（黑色不透明）。参数见第五节，编辑器可视化调整并写回 |
| `anchors` | 可选。预留扩展挂点（尾翼/车队横幅/涂装等），`position` 为模型局部空间坐标 |

**齐边推导**：运行时先按所选轮毂定轮位——x = ±(body_width − hub.outer)，轮毂外盘面齐车体最宽边缘；再套轮胎——胎中线对齐轮毂桶身几何中线（mid_x 偏移，左右镜像），胎侧自然包裹盘面。无轮毂资产或缺 outer 元数据时退回胎侧齐边（body_width − tire.width/2）。车体只需确保 `body_width` 等于车体最宽处半宽，任何盘面深浅/宽度的轮毂都能自动对齐，无需改车壳数据。

## 三、坐标与朝向约定

- 坐标一律为 **GLB 场景根空间**（米，Y-up，右手系），编辑器所见即此空间，运行时直接使用，不做二次换算。
- **车头朝 -Z**（与 Godot 前向一致；Blender 导出时车头朝 -Y 即可得到 glTF 的 -Z）。
- 轮件**轮轴沿 X**（与 `wheel.gd` 绕 `wheel_node.rotation.x` 滚动一致），并按**外侧朝 +X** 建模：轮毂盘面朝 +X、刹车盘从安装位（外侧摩擦面）向 -X（车内侧）延伸。运行时左侧轮位把外观件绕 Y 翻转 180°，使左右盘面/刹车盘朝向各自正确（轮胎左右对称，翻转无视觉差异）。
- GLB 场景原点与 `VehicleRigidBody` 原点重合：车壳 GLB 原点应在车身几何中心附近地面高度合适处。轴 y 按「标定即静态位」语义标注（vehicle.gd 自动补偿悬挂静态下垂，无需手动加行程余量）；注意它应与实际装配的胎半径匹配（车身静态离地 = 胎半径 − 轴 y），胎半径改了要复核轴 y。

## 五、材质语义标记（materials）与预设材质球（material_presets）

GLB 内的**材质名**是打标载体：美术在 DCC 中给大灯、刹车灯、车身分材质并命名（建议直接用 `headlight` / `brake_light` / `body`，或包含 head/brake/body 等可识别单词），导出后在编辑器「部件与材质」面板确认标记（支持按名称自动识别），保存写回 body.json。编辑器中点击材质条目可在视口高亮其所有网格，已绑定的槽位常显标记色（大灯黄 / 刹车灯红 / 车身蓝）。

运行时（game/car/brake_light.gd）按材质名（大小写不敏感精确匹配，退化子串匹配）在车壳内查找并复制材质（GLB 实例间共享材质资源，须每车独立副本）：

- `brake_light`：刹车时点亮红色自发光 + 灯组中心一盏红色 OmniLight3D。平时保持示位灯常亮红色自发光（0.4），刹车随 `brake_amount`（脚刹与手刹取大）经弹簧阻尼平滑升至高亮（~3.0）；**材质名支持逗号分隔多个**（如 602 的「材质.009, 材质.010」= 尾灯 + 高位刹车灯）；材质副本经 `surface_override_material` 按实例覆盖，多车各自独立不串色；
- `headlight` / `body`：暂只存元数据，后续车灯/车漆逻辑消费。

### 预设材质球（引擎效果）

`material_presets` 把 GLB 中同名材质整颗替换为引擎效果材质（game/car/material_presets.gd，车漆/钢琴烤漆为 StandardMaterial3D，灯罩/玻璃为 ShaderMaterial）。绑定键二选一（均可逗号分隔多个）：`material` 按 GLB 材质名匹配（大小写不敏感精确→子串，子串可一次绑一族如「车灯罩」同时命中「后车灯罩」）；`node` 按节点名匹配该网格全部表面——整块网格没分材质/材质未命名时用（如 602 直接建模的风窗玻璃节点「车玻璃」）：

| 槽位 | 效果 | 来源 | 暴露参数（编辑器可调，视口实时预览） |
| --- | --- | --- | --- |
| `paint` 车漆 | 纯色金属漆 + ORM 噪声亮片（粗糙度调制）+ 物理清漆 | three.js 官方示例 [webgl_materials_car](https://github.com/mrdoob/three.js/blob/dev/examples/webgl_materials_car.html) 车漆配方移植（MIT）：metalness 1.0 / roughness 0.5 / clearcoat 1.0 / clearcoatRoughness 0.03，落在 Godot StandardMaterial3D 内置清漆上 | `color` 颜色、`clearcoat` 清漆（`glancing` 已不消费，写默认值即可） |
| `piano_black` 钢琴烤漆 | 车身黑色部件用：近黑基底层 + 近镜面清漆的高反差镜面黑 | Godot StandardMaterial3D 内置清漆（与车漆同一管线，metallic 0 / roughness 0.4 / clearcoatRoughness 0.02） | `color` 颜色、`clearcoat` 清漆 |
| `headlight_lens` 大灯透明罩 | 透明 + 菲涅尔边缘 + 透明高光补偿 | [PBR Glass](https://godotshaders.com/shader/pbr-glass/)（aubrey，CC0；仅 Forward+，本项目即 Forward+） | `color` 颜色、`alpha` 透明度 |
| `glass` 车玻璃 | 黑色不透明 + 近镜面反射 + 边缘增亮 | 同上 PBR Glass | `color` 颜色（**完全不透明**，`alpha` 已废弃强制 1） |

参数默认值三端同构（app.js `PRESET_DEFAULT_PARAMS` / material_presets.gd `DEFAULT_PARAMS` / make_placeholder_assets.py `PRESET_DEFAULT_PARAMS`），改默认值需同步三处。生成器会按材质名自动绑定（paint: paint/漆/hull/body；lens: lens/灯罩/罩/cover；glass: glass/玻璃），识别不了的在编辑器手动绑定。

## 六、运行时装配（game/car/car_mesh_builder.gd）

- 车壳：隐藏 `arcade_car.tscn` 内嵌 `body`/`spoiler` MeshInstance3D，把 body.glb 场景挂到 `VehicleRigidBody`。
- 轮毂/轮胎：先按轮毂定 4 个轮位（x = ±(body_width − hub.outer)，外盘面齐边；无轮毂资产退回 x = ±(body_width − tire_width/2)，y/z 取对应轴），重定位 4 个 `Wheel*`（RayCast3D）物理挂点；每个 `wheel_node`（Node3D）下挂轮毂与轮胎 GLB 场景，偏移 `-center` 使枢纽落在挂点原点，**轮胎额外偏移 sign_x·mid_x**（胎中线对齐轮毂桶身几何中线，左右随朝向镜像）；`tire_radius` 取 tire.json 的 `radius`（入树前写入 vehicle 导出变量，由 `initialize()` 下发各物理轮）。
- 刹车盘：前/后轴各加载一款（`art/brakes/<id>/disc.glb`），挂到物理轮射线下的 `BrakePivot`（Node3D）——随悬挂行程与转向移动但**不随轮自转**（卡钳绕轮公转是穿帮），`wheel.gd` 的 `static_visual` 挂点每帧同步悬挂 y。appearance 可用 `brake_front`/`brake_rear` key 换装，缺省用默认前/后刹车盘。
- 左侧轮位（x < 0）所有轮件外观绕 Y 翻转 180°（见第三节朝向约定）。
- **轮件固定材质**（game/car/wheel_materials.gd）：轮件 GLB 交付不带贴图，挂载后统一替换为引擎侧 StandardMaterial3D——轮胎橡胶（albedo 取实测反射率 0.023 提亮至 0.028、metallic 0、roughness 0.9）、轮毂磨砂黑（深底色 metallic 1、roughness 0.65，暗金属边缘反射）、刹车盘亮面纯金属（不锈钢 F0 (0.669, 0.639, 0.598)、metallic 1、roughness 0.15）；**卡钳保留 GLB 原材质**（按材质名 kaqian/卡钳/caliper 识别跳过）。替换经 `material_override` / `surface_override_material`，不改共享网格资源。
- 任一资产缺失或解析失败 → 回退占位视觉并 `push_warning`，仓库克隆无 `art/` 也能正常运行。

## 七、工作流

1. 美术在 DCC（Blender 等）制作并导出 GLB 到 `art/cars/<id>/body.glb` 或 `art/wheels/<id>/wheel.glb`，`<id>` 为配表 Car-car 的 `id`；车壳给大灯/刹车灯/车身分材质命名（见第五节）；
2. 用 Chrome/Edge 打开 `tools/art_editor/server.py` 提供的 `http://localhost:8138/tools/art_editor/index.html`，选择 `art/` 目录：
   - **轮毂模式**：拖拽/数值设定中心点，可一键吸附包围盒中心，填 radius/width，保存写回 wheel.json；
   - **车壳模式**：左列车辆清单来自配表 `/api/cars`（配表加车自动出现），`art/cars/` 只标注每台车的资产状态；拖拽/数值设定前轴与后轴（y/z，x 恒 0）及 body_width 半宽，侧栏选择任一轮毂按齐边公式实时预览四轮装配（可开前轮转向/自转模拟检查轮眉干涉），「部件与材质」面板标记 headlight/brake_light/body 三个材质槽位，保存写回 body.json；
3. 在 Godot 编辑器中打开一次项目让 `.glb` 生成导入，运行游戏即按 JSON 装配。
