# 美术资源与车辆结构规范

车壳模型与轮毂模型分离管理。轮毂资产只存模型并定义**轮毂中心点**；车壳资产定义**四个轮位**。运行时（及编辑器预览）按「轮毂中心点对齐车壳轮位」装配，滚动/转向围绕该点旋转。

## 一、目录结构

```
F1/art/                      # 美术资源根（整目录 gitignore，不入库）
├── cars/
│   └── <car_id>/            # 车壳资产，如 brute_power
│       ├── body.glb         # 车壳模型
│       └── body.json        # 元数据：四个轮位等（编辑器读写）
└── wheels/
    └── <wheel_id>/          # 轮毂资产，如 sport_v1
        ├── wheel.glb        # 轮毂模型
        └── wheel.json       # 元数据：中心点等（编辑器读写）
```

- `<car_id>` / `<wheel_id>` 用小写字母、数字、下划线，同时是目录名与 JSON 里的 `id`。
- 模型统一 GLB（glTF 2.0 二进制），单位米。
- `tools/art_editor/index.html` 是元数据编辑器（代码入库，双击即用）。

## 二、元数据 Schema

### wheel.json（轮毂）

```json
{
  "version": 1,
  "id": "sport_v1",
  "name": "运动轮毂V1",
  "model": "wheel.glb",
  "center": [0.0, 0.0, 0.0],
  "radius": 0.3,
  "width": 0.2
}
```

| 字段 | 说明 |
| --- | --- |
| `center` | 轮毂中心点（模型局部空间，即轮轴穿过轮心的点）。运行时该点对齐车壳轮位，旋转围绕它进行 |
| `radius` | 可选。视觉半径（米），运行时同步给物理轮 `tire_radius`（决定悬挂射线长度） |
| `width` | 可选。轮宽（米），仅信息记录 |

### body.json（车壳）

```json
{
  "version": 1,
  "id": "brute_power",
  "name": "Brute Power",
  "model": "body.glb",
  "wheel_positions": {
    "front_left":  [-0.5, 0.35, -0.66],
    "front_right": [ 0.5, 0.35, -0.66],
    "rear_left":   [-0.5, 0.35,  0.66],
    "rear_right":  [ 0.5, 0.35,  0.66]
  },
  "anchors": {
    "spoiler": { "position": [0.0, 0.0, 0.0] }
  }
}
```

| 字段 | 说明 |
| --- | --- |
| `wheel_positions` | 四个轮位（模型局部空间），同时驱动物理轮挂点（RayCast3D）位置 |
| `anchors` | 可选。预留扩展挂点（尾翼/车队横幅/涂装等），`position` 为模型局部空间坐标 |

## 三、坐标与朝向约定

- 坐标一律为 **GLB 场景根空间**（米，Y-up，右手系），编辑器所见即此空间，运行时直接使用，不做二次换算。
- **车头朝 -Z**（与 Godot 前向一致；Blender 导出时车头朝 -Y 即可得到 glTF 的 -Z）。
- 轮毂模型轮面朝 +Z（符合 GEVP `wheel.gd` 对 `wheel_node` 的约定）。
- GLB 场景原点与 `VehicleRigidBody` 原点重合：车壳 GLB 原点应在车身几何中心附近地面高度合适处（轮位 Y 值即离地高度参考，现有占位车为 0.35）。

## 四、运行时装配（game/car/car_mesh_builder.gd）

- 车壳：隐藏 `arcade_car.tscn` 内嵌 `body`/`spoiler` MeshInstance3D，把 body.glb 场景挂到 `VehicleRigidBody`。
- 轮毂：按 `wheel_positions` 重定位 4 个 `Wheel*`（RayCast3D）物理挂点；每个 `wheel_node`（Node3D）下挂轮毂 GLB 场景，偏移 `-center`，使中心点落在挂点原点；`tire_radius` 取 wheel.json 的 `radius`。
- 任一资产缺失或解析失败 → 回退占位视觉并 `push_warning`，仓库克隆无 `art/` 也能正常运行。

## 五、工作流

1. 美术在 DCC（Blender 等）制作并导出 GLB 到 `art/cars/<id>/body.glb` 或 `art/wheels/<id>/wheel.glb`；
2. 用 Chrome/Edge 双击打开 `tools/art_editor/index.html`，选择 `art/` 目录：
   - **轮毂模式**：拖拽/数值设定中心点，可一键吸附包围盒中心，填 radius/width，保存写回 wheel.json；
   - **车壳模式**：拖拽/数值设定四个轮位（支持 X 镜像联动、网格吸附），侧栏选择任一轮毂实时预览四轮装配（拖拽实时跟随、可开前轮转向/自转模拟检查轮眉干涉），保存写回 body.json；
3. 在 Godot 编辑器中打开一次项目让 `.glb` 生成导入，运行游戏即按 JSON 装配。
