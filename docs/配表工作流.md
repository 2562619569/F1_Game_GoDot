# ModRacer 配表工作流（Excel → Godot）

> 表结构的设计依据见 [配表结构规划](game-design/配表结构规划.md)（含规划中的新表：全局/回合/掉落/排名奖励）。

基于社区工具 [GDExcelExporter](https://github.com/kaluluosi/GDExcelExporter)（`pip install gd_excelexporter`）搭建，导出器选用 **GDS2.0**（生成 GDScript 数据脚本，Godot 4 原生支持，类型即表格列）。

## 目录结构

```
config/                  # 配表工程（ee init 生成）
├── export.toml            # 导出配置（引擎/导出器/目录）
├── data/                  # ★ Excel 源表（数值唯一真理源头，进 git）
│   └── ModRacer.xlsx      #   车型-car / 改件-part / 地图-map 三张表
├── dist/                  # 导出产物（进 git，游戏直接读这里）
│   ├── settings.gd        #   autoload 入口，已注册到 project.godot
│   └── ModRacer/*.gd      #   每张表一个数据脚本
├── sample/                # 官方示例表（可删）
├── tools/
│   └── make_modracer_xlsx.py  # 首次建表脚本（仅参考，勿重复执行会覆盖表格）
└── verify/                # 配表回归验证场景
```

## 日常改表流程（策划）

1. 用 Excel/WPS 打开 `config/data/ModRacer.xlsx` 改数值、加行；
2. 在 `config/` 目录执行 `ee gen-all`（或运行 `config/gen_all.bat`）；
3. 回到 Godot 直接运行，数据即生效。无需改任何代码。

## 表格书写规范

**值与字段名只允许英文**（sheet 名、第 3 行字段名、数据单元格值）；`tr_string` 字段留给游戏内翻译。**第 2 行中文注释不会导出**，可用中文书写给人看；`*` 前缀的列和 `~` 前缀的 sheet 同样不会被导出。

每个 sheet 是一张表，sheet 名格式 `表名-变量名`（如 `Car-car` → `Settings.car`）。以 `~` 开头的 sheet 会被忽略（如 `~Cover`）。

每张表前三行为表头，之后每行一条记录：

| 行 | 内容 | 说明 |
| --- | --- | --- |
| 第1行 | 字段类型 | `int` `float` `string` `bool` `tr_string`(可翻译) `array` `dict` 等 |
| 第2行 | 中文注释 | 仅给人看，**不会导出** |
| 第3行 | 字段名 | **首列必须为 `id`**；`*` 前缀字段不导出 |

注意：
- 单元格内数组用 `a|b|c` 分隔；
- 删除某张表后需手动删掉 `dist/` 下对应的旧导出文件，`settings.gd` 里的引用也要重新生成（删掉 `dist/settings.gd` 再 `ee gen-all`）。

## 现有表结构

### Car-car（3 行）
- 展示层：`id, name, drive(RWD/FWD/AWD), top_speed, accel, handling, weight, perf_slots, func_slots, desc, grip_road, grip_offroad`
- 物理基础参数（对应 `addons/gevp/scripts/vehicle.gd` 同名导出变量）：`max_torque, max_rpm, final_drive, gear_ratios(array), front_torque_split, max_steering_angle, steering_speed, brake_force_multiplier, coefficient_of_drag, frontal_area, front_weight_distribution, center_of_gravity_height_offset, inertia_multiplier`

### Part-part（14 行）
- 基础字段：`id, name, category(engine/tires/aero/chassis/tactical), rarity(1-4)`
- 性能加成（百分比/数值，性能类专用）：`top_speed, accel, grip_road, grip_offroad, grip_wet, aero, landing, mass`
- 战术参数（功能类专用）：`cooldown(秒), ammo(单回合弹药), duration(效果持续秒)`
- 战术效果：`effect(none/slow_spin/stealth/nitro_push), power(强度，按 effect 解释)`

### Map-map（4 行）
`id, name, desc`——环境/天气不在配表，存于地图 env 文件 `game/race/tracks/data/map_<id>_env.json`（见 WeatherEnv / 地图环境插件）

### Game-game（6 行）
键值表：`id, key, value, note`（局间整备时长、回合数、锁定距离等全局数值）

### Round-round（4 行）
`id, name, is_final, time_limit, map_pool(a|b|c)`

### Loot-loot（2 行）
`id, route(main/hazard), drop_count, rarity_weights(r1|r2|r3|r4), category_pool, guarantee_rarity`

### RankReward-rank_reward（8 行）
`id(名次), reward_count, reward_rarity_min, grid_next(下回合发车位)`

## 游戏内读取方式

`config/dist/settings.gd` 已注册为 autoload `Settings`（见 `project.godot` 的 `[autoload]` 段）：

```gdscript
var car := Settings.car.data[1]          # 按 id 取车型
print(car.name, car.top_speed)           # 狂暴马力型 320

for id in Settings.part.data:            # 遍历所有改件
    var p = Settings.part.data[id]
    if p.category == "tactical":
        print(p.name, p.cooldown, p.ammo)
```

## 回归验证

改表导出后可运行 `config/verify/verify_config.tscn` 场景，它会把三张表的抽样数据和总行数写入 `config/verify/verify_result.txt`，用于快速确认导出链路没断。
